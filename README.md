# Pressure Sore Guard

ระบบดูแลผู้ป่วยหนักเพื่อป้องกันการเกิดแผลกดทับ (ICU pressure-injury prevention system) —
ต้นแบบ (prototype) ของระบบตาม workflow ที่ระบุไว้:

1. พยาบาล **สแกน QR code** ที่หัวเตียงเพื่อ Check-in และเริ่มนับเวลาดูแล พยาบาล 1 คน
   check-in ได้หลายเตียงพร้อมกัน (สัดส่วน 1:2 ขึ้นไป)
2. เมื่อครบเวลาพลิกตัว ระบบจะส่ง **Web Push Notification** ไปยังโทรศัพท์/เบราว์เซอร์ของพยาบาล
3. QR code เชื่อมกับ **แบบประเมินความเสี่ยง (checklist)** ที่ Admin เป็นผู้กำหนดคำถามและ
   คะแนน → ระบบคำนวณระดับความเสี่ยงและกำหนดรอบเวลาพลิกตัวให้อัตโนมัติ (ปรับได้ทุกเมื่อ)
4. มี **แดชบอร์ดกลาง** ให้หัวหน้าพยาบาล/แผนกดูภาพรวมการดูแลทุกเตียงแบบเรียลไทม์

## Tech stack

- **Next.js 14** (App Router) + TypeScript + Tailwind — Web App / PWA เดียวใช้ได้ทั้ง
  มือถือและคอมพิวเตอร์ ไม่ต้องติดตั้งจาก App Store
- **Prisma + SQLite** — ฐานข้อมูลสำหรับ dev/prototype (เปลี่ยนเป็น Postgres/MySQL ได้ง่าย
  โดยแก้ `provider` ใน `prisma/schema.prisma`)
- **Web Push (VAPID)** — แจ้งเตือนแบบ push ผ่านเบราว์เซอร์ ไม่ต้องพึ่งแอปภายนอก
- Session auth ด้วย PIN + JWT cookie (ไม่ใช้รหัสผ่านซับซ้อน เหมาะกับการใช้งานหน้างานที่ต้อง
  เข้า-ออกระบบบ่อย)

## เริ่มใช้งาน (development)

```bash
npm install
cp .env.example .env
# แก้ AUTH_SECRET ใน .env เป็นสตริงสุ่ม เช่นด้วย: openssl rand -base64 32

npm run generate:vapid      # สร้าง VAPID key แล้วนำไปใส่ใน .env (สำหรับ push notification)

npx prisma db push          # สร้างฐานข้อมูล SQLite ตาม schema
npm run db:seed             # ใส่ข้อมูลตัวอย่าง: admin, พยาบาล 3 คน, เตียง 6 เตียง, แบบประเมิน 1 ชุด

npm run dev                 # รันเว็บแอปที่ http://localhost:3000
npm run scheduler           # รัน worker แยก (คนละ terminal) สำหรับส่งแจ้งเตือนเมื่อครบเวลา
```

บัญชีตัวอย่างจาก seed:

| บทบาท | ชื่อ | PIN |
| --- | --- | --- |
| ผู้ดูแลระบบ | หัวหน้าพยาบาล (Admin) | `0000` |
| พยาบาล | พยาบาลสมศรี / อรทัย / วิภา | `1234` |

เตียงตัวอย่าง: `ICU-01` ถึง `ICU-06`

## Workflow ในระบบ

### 1. Admin ตั้งค่าระบบ (`/admin`)
- **เตียง & QR Code** — เพิ่ม/แก้ไขเตียง ผูกข้อมูลผู้ป่วย และพิมพ์ QR code ติดหัวเตียง
  (QR แต่ละอันชี้ไปที่ `/bed/<รหัสเตียง>/checkin`)
- **แบบประเมิน** — สร้าง/แก้ไขรายการคำถามประเมินความเสี่ยง พร้อมคะแนนแต่ละตัวเลือก และ
  กำหนดเกณฑ์ "คะแนนรวม → ระดับความเสี่ยง → รอบเวลาพลิกตัว (นาที)" การบันทึกจะสร้างเวอร์ชัน
  ใหม่โดยไม่ลบของเดิม (เก็บประวัติไว้อ้างอิงย้อนหลังได้)
- **บัญชีผู้ใช้งาน** — เพิ่มพยาบาล/แอดมิน ตั้ง/รีเซ็ต PIN เปิด-ปิดการใช้งานบัญชี

### 2. พยาบาล Check-in ที่หัวเตียง (`/bed/[code]/checkin`)
- สแกน QR → ถ้ามีผลประเมินก่อนหน้า เลือก "ใช้ผลประเมินเดิม" ได้ทันที หรือ "ทำแบบประเมินใหม่"
- ระบบคำนวณคะแนนรวม จับคู่กับเกณฑ์ที่ Admin ตั้งไว้ → ได้ระดับความเสี่ยงและรอบเวลาพลิกตัว
- เริ่มนับเวลาทันทีที่ Check-in; ปุ่ม "พลิกตัวแล้ว" รีเซ็ตรอบเวลาและบันทึกประวัติการพลิกตัว
- สแกนเตียงเดิมซ้ำ (เช่น เปลี่ยนเวร) จะ handover ให้พยาบาลคนใหม่โดยอัตโนมัติ

### 3. เตียงของฉัน (`/my-beds`)
- พยาบาลเห็นทุกเตียงที่ตนเอง check-in อยู่พร้อมนับถอยหลังแบบเรียลไทม์ (รองรับดูแลหลายเตียง
  พร้อมกัน) และปุ่มเปิดรับการแจ้งเตือน Push

### 4. แดชบอร์ดกลาง (`/dashboard`)
- ภาพรวมทุกเตียงที่กำลังดูแล: พยาบาลผู้รับผิดชอบ ระดับความเสี่ยง เวลาที่พลิกตัวล่าสุด และ
  เวลาที่เหลือ/เลยกำหนด (ไฮไลต์สีแดงเมื่อเลยเวลา) กรองตามวอร์ดได้ รีเฟรชอัตโนมัติทุก 10 วินาที

### 5. การแจ้งเตือน (Web Push)
- `scripts/scheduler.ts` เป็น background worker ที่ตรวจสอบทุก 20 วินาทีว่ามีเตียงไหนครบ
  เวลาพลิกตัว แล้วส่ง push ไปยังอุปกรณ์ของพยาบาลที่ดูแลอยู่ (ผ่าน service worker
  `public/sw.js`) และแจ้งเตือนซ้ำแบบเร่งด่วนหากเลยเวลาไปแล้ว 10 นาทีโดยยังไม่กดพลิกตัว
- ต้องรันคู่กับเว็บแอปเสมอ (ดูคำสั่งด้านบน) — ใน production ควรรันเป็น long-lived worker
  process หรือ scheduled job ตามโครงสร้าง infra ที่ใช้จริง

## โครงสร้างโปรเจกต์ (ส่วนสำคัญ)

```
prisma/schema.prisma        โมเดลข้อมูล (User, Bed, ChecklistTemplate, Assessment,
                             CheckIn, TurnLog, PushSubscription, NotificationLog)
prisma/seed.ts               ข้อมูลตัวอย่างสำหรับเริ่มทดสอบ
src/lib/checklist.ts         ตรรกะคำนวณคะแนน + จับคู่เกณฑ์ความเสี่ยง (ใช้ร่วม client/server)
src/lib/auth.ts, pin.ts      session JWT (edge-safe) และ PIN hashing (node-only)
src/middleware.ts            ป้องกันเส้นทางที่ต้อง login / เฉพาะ admin
src/app/bed/[code]/checkin   หน้า Check-in จากการสแกน QR
src/app/my-beds              หน้าเตียงของพยาบาลที่ล็อกอิน
src/app/dashboard            แดชบอร์ดกลาง
src/app/admin/*              หน้าจัดการเตียง / แบบประเมิน / บัญชีผู้ใช้
scripts/scheduler.ts         worker ส่งแจ้งเตือนเมื่อครบ/เลยเวลาพลิกตัว
public/sw.js                 service worker รับ push notification (PWA)
```

## ข้อควรทราบสำหรับก่อนใช้งานจริง (production readiness)

โปรเจกต์นี้เป็น **ต้นแบบที่ใช้งานได้จริง (working prototype)** เพื่อสาธิต workflow ครบวงจร
ก่อนนำไปใช้งานจริงในหน่วยงาน ควรพิจารณาเพิ่มเติม:

- เปลี่ยนฐานข้อมูลจาก SQLite เป็น Postgres/MySQL (แก้ `datasource` ใน schema.prisma) และใช้
  `prisma migrate` แทน `db push` เพื่อจัดการ migration อย่างเป็นระบบ
- อัปเกรด Next.js เป็นเวอร์ชันล่าสุด (โปรเจกต์นี้ pin ไว้ที่ 14.2.x ซึ่งยังมีช่องโหว่ที่แก้ไข
  เฉพาะใน major version ถัดไป — ดูผล `npm audit`) และทดสอบผลกระทบต่อ App Router APIs
  (เช่น `cookies()`/`params` ที่เปลี่ยนเป็น async ใน Next 15+)
- รัน scheduler เป็น proper background job/queue (เช่น cron, BullMQ, หรือ serverless
  scheduled function) แทนการรัน `npm run scheduler` แบบ manual
- เพิ่มช่องทางแจ้งเตือนสำรอง (เช่น LINE Notify) กรณีอุปกรณ์ไม่รองรับ/ปิดการแจ้งเตือน Push
- ทบทวนเนื้อหาแบบประเมินร่วมกับทีมพยาบาล/แพทย์ (ตัวอย่างในระบบนี้เป็นแบบจำลองเพื่อสาธิตการ
  ให้คะแนนเท่านั้น ไม่ใช่เครื่องมือประเมินทางคลินิกที่ผ่านการรับรอง)
- เพิ่ม audit log / รายงานสรุปเชิงสถิติ (compliance reporting) จากข้อมูล `TurnLog` ที่เก็บไว้แล้ว
